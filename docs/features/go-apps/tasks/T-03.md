# T-03: Dry-run runs connectors that declare it safe

- **Roadmap:** ../ROADMAP.md · **Phase:** 2 · **Repo:** release-cli · **Base branch:** release/go-apps-p2 (PR targets it, not main) · **Branch:** feature/dry-run-connectors
- **Depends on:** phase 1 merged · **Model:** sonnet · **Review tier:** read

## Goal
`release --dry-run` can show the real artifacts: a connector that says it is safe runs in dry-run with
`dry_run: true` and an output folder, and its result reaches the next connector, while nothing is tagged,
pushed or published.

## Scope
- Files: `connectors.py` (`questions` answer accepts `"dry_run": "safe"`; request adds `out_dir`), `cli.py`
  (dry-run: after the existing checks, run safe connectors in order into `<tmp>/release-dry-run/<repo>/<version>/`,
  print it, `--json` adds `dry_run_dir` and `connectors`), README "Writing a connector",
  `tests/fixtures/fake_connector.py`.
- Out of scope: any real connector (T-04 to T-07).

## Contract
Roadmap → Decisions (dry-run builds). In dry-run, `sha` is HEAD and `tags` are the planned ones (not on origin).
Connectors without the flag behave as today. No run state is saved for a dry-run. A failure exits 1.

## Acceptance criteria (executable)
- [ ] A safe fake connector runs in dry-run, writes into `out_dir`, and the next safe one sees its result in `prior`; an unsafe one only asks — `pytest tests/test_connectors_contract.py -q`
- [ ] Dry-run saves no run state and creates no tag — `pytest tests/test_tag_boundary.py -q`
- [ ] Lint and the full suite — `uvx ruff check . && uv run --with pytest pytest -q`
- [ ] Nothing private in the diff — `git diff origin/main --name-only | xargs grep -niEf <forbidden list from the brief>` finds nothing
- [ ] README section updated; tests follow the repo's test rules (realistic bugs, survive refactors)

## Result (filled by the worker)

- **PR:** https://github.com/GutiNicolas/release-cli/pull/22 (not reviewed per task).
- **Done.** A connector's `questions` answer accepts `"dry_run": "safe"` (anything else is a protocol error). `release --dry-run`, after its existing checks, runs the safe connectors in `order` with `dry_run: true` and `out_dir` = `<tmp>/release-dry-run/<repo>/<version>/`; each result reaches the next in `prior`. Unsafe connectors only ask, as before. Nothing is tagged, pushed or saved. `--json` adds `dry_run_dir` and `connectors`. The run request has a new `out_dir` field (`null` unless it is a dry-run `run`).
- **Criteria** (all run here):
  - Safe fake runs, writes into `out_dir`, the next safe one sees it in `prior`, the unsafe one only asks: `pytest tests/test_connectors_contract.py -q` passes (new tests: chain and `prior`, stale folder emptied, failure stops the chain, no config written, flag validation).
  - No run state, no tag, tree clean, HEAD unchanged, through the real CLI with a bare remote; exit 1 on a failing safe connector: `pytest tests/test_tag_boundary.py -q` passes (2 new tests).
  - `uvx ruff check .` clean; full suite passes, 0 failed.
  - Forbidden-list grep over `git diff origin/main --name-only`: no match.
  - README: request fields, the `dry_run` answer, new "Dry run with connectors" subsection.
- **Decisions** (not spelled out in the spec):
  - Failure exit: only a failure of a connector that answered `safe` exits 1 (checked in `cli.py` from `report["connectors"]`). A question-time failure of an unsafe connector stays logged and ignored, as today ("connectors without the flag behave as today").
  - Questions of a safe connector are asked like a real run (`--defaults` takes defaults, otherwise it prompts), but `persist: project` answers are not written to the config (a dry run writes nothing).
  - A saved `interrupted` job is never resumed in a dry run.
  - `out_dir` is created (emptied first, via `shutil.rmtree`) only when at least one safe connector will run; before that it is `null` and `dry_run_dir` is `null` in `--json`. `connectors` in `--json` lists only the safe ones that ran (`{status, result, error, job_id}`), not the unsafe ones.
  - `run_chain` / `post_push` take an optional `report` dict (out-parameter) to hand the dir and outcomes to the CLI; return value unchanged.
  - Failure text in a dry run says nothing was tagged/pushed/published instead of the "tag stays pushed, resume" hint; Ctrl-C likewise.
  - `tests/conftest.py` now points `TMPDIR` at a per-test folder so dry-run tests never write to the real temp dir.
- **Where to look:** `connectors.run_chain` (dry-run branches: `dry_safe`, the `out_dir` block before the run loop, `record`), `cli.py` dry-run block, the "Dry run with connectors" README subsection.
- **Not done / for later:** nothing uses the flag yet (T-04 `go-build` is the first consumer). The fixed `<tmp>/release-dry-run/<repo>/<version>/` path means two concurrent dry runs of the same release share a folder.
