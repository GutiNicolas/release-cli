# T-01: `multi` question type in connector protocol 1

- **Roadmap:** ../ROADMAP.md · **Phase:** 1 · **Repo:** release-cli · **Base branch:** release/jira-slack-p1 · **Branch:** feature/multi-question
- **Depends on:** none · **Model:** sonnet

## Goal
A connector can ask "pick from this list" with everything pre-ticked, and the user reviews it in the terminal.

## Scope
- Files: `release_cli/connectors.py` (`_parse_question`, `Question.value_error`, `describe`, `_ask_one`), `release_cli/prompts.py` (new `ask_multi`), README "Writing a connector", `tests/fixtures/fake_connector.py`.
- Out of scope: any connector using it (T-03).

## Contract
Roadmap → Contracts → `multi` question.

## Acceptance criteria (executable)
- [ ] Parse: invalid shapes rejected with a clear reason (default not a subset, duplicate values, `persist` set, bad `other.pattern`) — `pytest tests/test_protocol_questions.py -q`
- [ ] Terminal: toggle by number, `+KEY` (validated by `other.pattern`), `-KEY`, Enter accepts; `--defaults` takes `default`; closed stdin is a recorded failure — `pytest tests/test_connectors_contract.py -q`
- [ ] `--dry-run` lists the options and the default — same file
- [ ] Old connectors unaffected; `uvx ruff check .`
- [ ] Repo rules: test-suite-prune (no e2e suite in this repo)

## Result (filled by the worker)

- **Done.** `multi` is parsed in `_parse_question` (new `_parse_multi`), validated in `Question.value_error` (list of strings, no duplicates, each an option or matching `other.pattern`), shown by `describe`, and asked by `prompts.ask_multi` (numbers toggle, `+KEY`, `-KEY`, Enter accepts; answer = option order, then extras in the order added; extras are listed and can be toggled off by number). `--defaults` returns `default`; closed stdin raises `EOFError`, which the existing `_ask_one` turns into the recorded `MissingAnswer` failure. README "Writing a connector" and the `multi` fake behavior are updated.
- Parse rejections (each with a reason): default not a subset of the option values, duplicate default values, duplicate options, `persist` other than `none`, invalid or missing `other.pattern`, malformed option, empty options without `other`.
- Decisions inside the contract: `default` omitted means nothing ticked; `options` may be empty only when `other` is set; `persist: "none"` written explicitly is accepted; `+KEY` of an existing option ticks it.
- Criteria: parse → `tests/test_protocol_questions.py` pass; terminal, `--defaults`, closed stdin and `--dry-run` listing → `tests/test_connectors_contract.py` pass; old connectors → full suite `uv run --with pytest pytest -q` passes; `uvx ruff check .` clean.
