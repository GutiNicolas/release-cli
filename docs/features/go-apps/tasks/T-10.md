# T-10: `gh-workflow` connector, attestations, npm provenance

- **Roadmap:** ../ROADMAP.md · **Phase:** 5 · **Repo:** release-cli · **Base branch:** release/go-apps-p5 (PR targets it, not main) · **Branch:** feature/gh-workflow
- **Depends on:** phase 4 merged and GitHub Actions has quota · **Model:** sonnet · **Review tier:** read

## Goal
A release cut on a laptop builds and publishes in the app's GitHub Actions workflow, so artifacts get build
provenance and the npm package is published with provenance.

## Scope
- Files: new `release_cli/gh_workflow.py` (dispatches `workflow_dispatch` for the tag with `gh workflow run`, waits
  with `gh run watch`, resumable by run id), `examples/github/release.yml` (installs release-cli, runs
  `release connectors run "$TAG" --defaults --json --only go-build,github-release,npm-publish,homebrew-tap`, then
  `actions/attest-build-provenance` over `dist/<version>/*`; npm with `--provenance` and `id-token: write`),
  `npm_publish.py` (`provenance = true` option), README.
- First step: verify (docs or a test repo) that npm provenance and attestations need the CI identity token; write
  the finding in Result.

## Contract
Local chain becomes `gh-workflow`, `slack-notify`. The workflow runs the phase 2 and 3 connectors unchanged; the key-based `sign` stays so old verify instructions keep working.
