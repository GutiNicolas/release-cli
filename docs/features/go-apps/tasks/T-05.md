# T-05: `github-release` uploads the manifest's assets

- **Roadmap:** ../ROADMAP.md · **Phase:** 2 · **Repo:** release-cli · **Base branch:** release/go-apps-p2 (PR targets it, not main) · **Branch:** feature/release-assets
- **Depends on:** T-04 integrated · **Model:** sonnet · **Review tier:** read

## Goal
The GitHub Release of a Go app carries the archives, `checksums.txt`, the installer and the formula, so people can
download and verify them.

## Scope
- Files: `github_release.py` (when `prior["go-build"]` is ok, upload every manifest artifact except the npm tgz
  with `gh release upload --clobber` after create; declare `dry_run: safe` and list the assets in dry-run), README.
- Out of scope: other build connectors (the manifest is the interface).

## Contract
Roadmap → Contracts (results). Resume reuses the release and re-uploads only missing assets. RC = pre-release (as today).

## Acceptance criteria (executable)
- [ ] With a fake `gh` on PATH: create then one upload per asset; resume uploads only the missing ones; dry-run calls no `gh` and lists them — `pytest tests/test_github_release.py -q`
- [ ] Without `go-build` in `prior` behaviour is unchanged — same file
- [ ] Lint and the full suite — `uvx ruff check . && uv run --with pytest pytest -q`
- [ ] Nothing private in the diff — `git diff origin/main --name-only | xargs grep -niEf <forbidden list from the brief>` finds nothing
- [ ] README section updated; tests follow the repo's test rules (realistic bugs, survive refactors)
