# T-06: `npm-publish` connector (lockstep)

- **Roadmap:** ../ROADMAP.md · **Phase:** 2 · **Repo:** release-cli · **Base branch:** release/go-apps-p2 (PR targets it, not main) · **Branch:** feature/npm-publish
- **Depends on:** T-04 integrated · **Model:** sonnet · **Review tier:** read

## Goal
The app's npm package is published with the same version as the binary, on the same release, without editing the
tracked `package.json`.

## Scope
- Files: new `release_cli/npm_publish.py` (built-in, declares `dry_run: safe`), README section, the fixture's
  `packages/hello-js`.
- Copies `package_dir` to a temp dir, sets `version` there, `npm pack` into the go-build dir (adds the tgz to the
  result), then `npm publish <tgz> --tag <latest|next> --access <access>`; dry-run uses `npm publish --dry-run`.

## Contract
Roadmap → Contracts (`[connectors.npm-publish]`, results, secrets). Token: secret `npm-token` written to a temp
`.npmrc` (never logged), else the user's `npm login`. A version already on the registry → ok with `published: false`
(resume-safe), checked with `npm view <name>@<version> version`.

Notes for the integrate session:
- Additions beyond the Contracts: optional `registry` and `token_secret` settings. The default secret `npm-token` is optional (falls back to `npm login`); a `token_secret` that is named but unset is an error.
- The tarball is also appended to `manifest.json` in the `go-build` dir (`kind: "npm"`) and returned as `result.artifact`. The order in the roadmap runs `github-release` before `npm-publish`, so T-05's upload will not see the tgz unless the order changes or T-05 picks it up another way.
- `package_dir` is copied from the working tree, not from the tagged commit (so build outputs the package needs, if ignored by git, are included); `node_modules` and `.git` are skipped.
- Dist-tag rule: any version with a `-` suffix gets `rc_dist_tag`, otherwise `latest`.
- Fails when `go-build` did not run ok earlier in the chain (the tarball goes into its output folder).
