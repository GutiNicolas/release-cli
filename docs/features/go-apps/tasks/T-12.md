# T-12: `npm-publish` builds the package from the release commit

- **Roadmap:** ../ROADMAP.md · **Phase:** 4 · **Repo:** release-cli · **Base branch:** release/go-apps-p4 (PR targets it, not main) · **Branch:** fix/npm-build
- **Depends on:** T-11 merged · **Model:** sonnet · **Review tier:** read

## Goal
A TypeScript package whose `prepack` builds (`tsc`) publishes from the release commit. Today `npm-publish` extracts
only `package_dir` with `git archive` into a temp folder and runs `npm pack` there: no `node_modules`, no `dist/`
(git-ignored), so `prepack` fails with `tsc: command not found`. Found by the first consumer's dry-run (an npm
workspace package with a root `package-lock.json`).

## Scope
- Files: `release_cli/npm_publish.py`, its tests, README (npm-publish section), the Go fixture if it needs a
  TypeScript package with a `prepack` build.
- Still from the release commit (T-06's fix stays: never the working tree). Extract the whole commit (`git archive
  <sha>`) into the temp folder instead of only `package_dir`; set the version in `package_dir/package.json` there as
  today.
- Install dependencies in that folder before packing: when the archive's root has `package-lock.json`, run `npm ci`
  at the root (workspaces get their dev dependencies); else when `package_dir` has one, run `npm ci` there; else no
  install (today's behaviour). Then `npm pack` `package_dir` (its `prepack` runs).
- A failed install or pack fails the step with npm's last lines (token redacted, as today) and a hint naming the
  folder it ran in.
- Out of scope: a configurable build command, pnpm/yarn, caching `node_modules`.

## Acceptance criteria (executable)
- [ ] Fixture: an npm workspace (root `package-lock.json`, `packages/acme-cli` with `"prepack": "tsc -p ."` and a
  `typescript` devDependency, `dist/` git-ignored): `release --dry-run -rc --defaults --json` exits 0 and the tgz in
  the dry-run folder holds `package/dist/index.js` and the RC version — a test (skips when `npm` is not on PATH), and
  run once by hand
- [ ] A package with no lockfile anywhere packs as today (existing tests unchanged and green)
- [ ] A `prepack` that fails makes the step fail with npm's output and the folder in the hint — a test
- [ ] The working tree is never read: an uncommitted change in `package_dir` does not reach the tgz — a test
- [ ] Lint and the full suite — `uvx ruff check . && uv run --with pytest pytest -q`
