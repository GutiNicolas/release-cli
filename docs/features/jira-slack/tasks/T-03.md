# T-03: built-in `jira` connector

- **Roadmap:** ../ROADMAP.md · **Phase:** 1 · **Repo:** release-cli · **Base branch:** release/jira-slack-p1 · **Branch:** feature/jira-connector
- **Depends on:** T-01, T-02 integrated · **Model:** sonnet

## Goal
`release connector add jira`: after a release (after the deploy's SUCCESS when a deploy connector is in the chain),
the reviewed tickets move with the project's RC or final transition.

## Scope
- Files: new `release_cli/jira_connector.py` (protocol like `cursor_review.py`), `BUILTINS` in `connectors.py`,
  commit-range helper shared with `github_release.py` (extract, don't duplicate), README section.
- Out of scope: fixVersion, Jira Data Center.

## Contract
Roadmap → Contracts (`multi`, secrets, config keys, `jira` result). Jira Cloud REST v3: `GET /rest/api/3/issue/{key}?fields=summary,status`,
`GET /rest/api/3/issue/{key}/transitions`, `POST /rest/api/3/issue/{key}/transitions`. stdlib `urllib` only.

## Behaviour
- `questions`: keys from the commit range (regex `[A-Z][A-Z0-9_]+-\d+`); fetch summary and status for the label;
  `multi` with the project's keys ticked, others unticked; first time in a project: `project_key` (text, persist)
  and `rc_transition` / `final_transition` as `choice` from the transitions Jira offers (persist). Not configured
  (`[jira] base_url`/email or secret missing) → `applies: false` with how to set it.
- `run`: skip unless the deploy in `prior` is SUCCESS (when a deploy connector exists); apply the transition by
  name per ticket; unavailable → `skipped` with the ticket's current status; HTTP error → `failed` for that ticket;
  `ok` false only when Jira is unreachable or auth fails. Idempotent on resume (a ticket already in the target status → skipped).

## Acceptance criteria (executable)
- [ ] Against a fake Jira (local `http.server` in the test): checklist built from commits, transition per project, skipped/failed reporting, resume — `pytest tests/test_jira_connector.py -q`
- [ ] The token is never in the request config, run state, or output — same file
- [ ] `uvx ruff check .`; repo rules: test-suite-prune
- [ ] Manual check documented in the PR: one real RC on a sandbox Jira project
