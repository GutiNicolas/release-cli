# T-01: Configurable tag format (`v` tags)

- **Roadmap:** ../ROADMAP.md · **Phase:** 1 · **Repo:** release-cli · **Base branch:** release/go-apps-p1 (PR targets it, not main) · **Branch:** feature/tag-format
- **Depends on:** none · **Model:** sonnet · **Review tier:** evidence

## Goal
A project chooses its tag names. A Go app tags `v1.4.0-rc0`; Maven, Gradle and sbt keep `1.4.0-rc0` and
`{artifact}-1.4.0-rc0` with no config change.

## Scope
- Files: `config.py` (`tag_format`, list of templates with `{version}` and `{artifact}`), `cli.py` (planned tags,
  `_preflight`), `commands.py` (`release_version_of`, `undo`, `history_data`, `status_data`, `notes`),
  `github_release.py` (`_plain`, `latest_tag`, notes range), `hotfix.py` (`_target`), `gitops.remote_tags_of`.
- Out of scope: the `go` tool (T-02).

## Contract
Roadmap → Decisions (tag format). Default `["{version}", "{artifact}-{version}"]`. The first template is the primary
tag (notes, `connectors run <tag>`, history). Every command accepts any configured form of a tag. A `v` prefix is
parsed only when a template has it.

- **Decisions** (not spelled out in the spec):
  - Connector request: `release_version` stays the bare version; new `tag` (primary tag) and `tag_format` fields. Everything that is a git ref or a state key uses the primary tag: `github-release` (release name, notes range), `jira` (commit range, resume hint), `cursor-review` (job key), `slack-notify` (notes range), saved run state (`runs/<repo>/<primary tag>.json`). For the default format the primary tag equals the old `release_version`, so existing state files and connectors are unaffected. Connectors reading only `release_version` and using it as a tag will be wrong for a `v` format; that is why `tag` exists.
  - History, `status`, `notes` (no argument) and the previous-tag lookup walk only the **primary** form, so a repo with two templates lists each release once. Switching `tag_format` on a repo that already has releases hides its older tags there (documented in the README).
  - `{version}` must appear exactly once per template; `{artifact}` at most once; literal text limited to `A-Za-z0-9._/+-`. A `v` (or any prefix) is parsed only when a template has it; a tag in none of the forms is refused with the expected forms listed.
  - Maven `<scm><tag>`: still `{artifact}-{version}` when that form is configured, otherwise the primary tag.
  - `hotfix` looks up and branches from the **primary** tag of the version, whichever form was typed; its "already has tags" check now covers every configured form (it previously saw only the plain form locally).
  - `gitops.remote_tags_of(version)` became `remote_tags_matching(patterns)` (ls-remote globs rendered from the templates); hotfix is its only caller.
  - `release history` now loads the project config (to know the primary form); with no config it falls back to the default form, but a config that fails to parse now fails `history` too.
  - A local `.release` that does not set `tag_format` does not override the team `release.toml`'s.
