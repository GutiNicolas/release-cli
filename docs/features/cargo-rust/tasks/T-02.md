# T-02: `cargo` tool: detection, `Cargo.toml` + `Cargo.lock` versions

- **Roadmap:** ../ROADMAP.md · **Phase:** 1 · **Repo:** release-cli · **Base branch:** release/cargo-rust-p1 (PR targets it, not main) · **Branch:** feature/cargo-tool
- **Depends on:** none · **Model:** sonnet · **Review tier:** evidence

## Goal
`release --init` sets up a Rust repository, and `release -rc` / `-fv` / hotfix bump the version in `Cargo.toml`
(and `Cargo.lock` when committed) and tag it `vX.Y.Z...`, exactly as they do for a Go app. Nothing is built yet.

## Scope
- New `release_cli/adapters/cargo.py` (`CargoAdapter`, modelled on `adapters/go.py`), registered in
  `adapters/__init__.py`.
- Touch points: `config.py` (`Tool`, `TOOLS`), `cli.py:98` (`--tool` choices), `detect.py:21` (Cargo.toml moves from
  hint to detected tool `cargo`), `init.py:99-111` and `:173-177` (default `tag_format = ("v{version}",)` for
  `cargo`; ask for `artifact` when the root is a virtual workspace, default: the only `[[bin]]`/member name if
  there is exactly one), `doctor.py:201` (a `cargo` branch: `cargo` on PATH, the version readable). README: the
  supported-tools list and a short "Rust (Cargo)" section.
- New fixture `tests/fixtures/cargo-app/`: virtual workspace, `[workspace.package] version = "0.1.0-rc0"`,
  `crates/hello` (bin `hello`, prints `env!("CARGO_PKG_VERSION")`) and `crates/greet` (lib, used by hello), both
  `version.workspace = true`, no external dependencies, committed `Cargo.lock`, LICENSE, README. Names `acme`-style only.
  T-04 extends this fixture.
- Tests: `tests/test_cargo_tool.py`.
- Out of scope: building anything (T-04), packaging (T-03).

## Contract
Roadmap → Decisions (`cargo` adapter, `Cargo.lock`, version format, tags) and Contracts (project config).
- **Read** (`tomllib`): `[workspace.package] version` if present, else the root `[package] version`. Members come from
  `[workspace] members` (globs expanded with `Path.glob`, minus `exclude`). A member with a literal `version` → 
  `AdapterError` naming its `Cargo.toml`. A version not matching `X.Y.Z[-rcN][-SNAPSHOT]` → `AdapterError`.
- **Write:** text edits only (no new dependency): replace the value on the one `version = "..."` line inside the
  right table of the root `Cargo.toml`, keeping quotes, spacing, comments and line endings; in `Cargo.lock`, for each
  member name, the `version` line of its `[[package]]` block that has no `source` line. `paths()` returns both files
  (the lock only when it exists and is tracked), so the release commit includes them.
- **Non-functional:** no `cargo` call from the adapter (it must work where Rust isn't installed).

## Decision (don't reopen)
- **Chosen:** version in `Cargo.toml`, plain text edits — Cargo already has a version and the repo has zero deps.
- **Rejected:** a `VERSION` file (go-style), `cargo set-version` / `cargo-edit`, adding `tomlkit`. Don't implement them.
- **Explicitly out of scope:** per-member versions (one version per repository), `cargo publish`.

### Decisions not in the spec
- The fixture starts at `0.1.0-rc0` as specified, but `-rc` on it gives `0.1.0-rc1` (an open candidate increments). To get the `v0.1.0-rc0` tag the criterion asks for, the test first writes `0.0.0-SNAPSHOT` through the adapter (also exercising `write`), commits, then runs `-rc`.
- Artifact default for a virtual workspace: the only binary (`[[bin]]` names, or a member with `src/main.rs`); else the only member; else the folder name. `--init` still asks for it through its existing "Artifact name" prompt (as for every tool), so no new prompt.
- "Tracked" lock = exists and `git ls-files --error-unmatch` succeeds; outside a git work tree an existing lock counts as tracked.
- `write` computes both files before writing either, and refuses a `version` line count other than one in the target table.
- `doctor` only adds a warning when `cargo` is not on PATH (the version is already checked by the generic "project version" line); no `cargo test` hook offer in `--init` (only a hint line), not asked for.
- Fixture `Cargo.lock` is `version = 3`, written by hand (see Not verified).
- README: added a Rust badge and the "Rust (Cargo)" section; `docs/` untouched.

### Assumptions
- Workspace members are those in `[workspace] members` (globs) minus `exclude`, plus the root `[package]` if any. Path dependencies that Cargo adds as implicit members are not followed.
- A member without a `version` key (defaults to 0.0.0) is left alone, in both files.
- Only a `version = "..."` line directly in the right table is edited; dotted forms such as `package.version = "1"` are not supported and fail with "expected one version line".

### Not verified
- `cargo` is not installed on this machine: the criterion "`cargo metadata --locked --offline` exits 0 after `write`" ran as skipped. The fixture `Cargo.lock` was written by hand in cargo's format, not generated, and never checked by cargo. Run `pytest tests/test_cargo_tool.py -q` on a machine with Rust before the release PR merges.
- `doctor` on a cargo project (warning branch) has no test.
