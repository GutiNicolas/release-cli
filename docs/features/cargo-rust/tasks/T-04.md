# T-04: `cargo-build` connector and Rust fixture

- **Roadmap:** ../ROADMAP.md · **Phase:** 2 · **Repo:** release-cli · **Base branch:** release/cargo-rust-p2 (PR targets it, not main) · **Branch:** feature/cargo-build
- **Depends on:** phase 1 merged, T-01 gate passed (read `spike-windows.md` first) · **Model:** sonnet · **Review tier:** read (manifest `build` feeds provenance)

## Goal
After the push (or in a dry-run), a Rust app's binaries for every configured target exist as archives (plus the bare
`.exe` for Windows) with checksums and a manifest, built from exactly the tagged commit with the version stamped in,
ready for `sign` and `github-release` unchanged.

## Scope
- New `release_cli/cargo_build.py` (built-in, entry point `cargo-build`, declares `dry_run: safe`, `applies: false`
  without a root `Cargo.toml`), built on `release_cli/packaging.py` (T-03), modelled on `go_build.py`.
- Windows: implement only the path(s) `docs/features/cargo-rust/spike-windows.md` proved (msvc via `cargo xwin build`
  and/or gnu via mingw). A triple whose path the spike did not prove fails with "not supported yet".
- Toolchain checks at the start of `run`, before any build: `cargo`; each target in
  `rustup target list --installed`; `cargo-xwin` (msvc off Windows) or `x86_64-w64-mingw32-gcc` (gnu); plus any
  licence or env step the spike recorded. Each failure names the exact install command (`rustup target add <t>`,
  `cargo install --locked cargo-xwin`, `brew install mingw-w64`). Never accept a licence on the user's behalf.
  `doctor.py`: report the same checks when `[connectors.cargo-build]` is configured.
- Targets: allowed per Roadmap → Decisions (host, other macOS arch, Windows); a Linux triple from macOS fails before
  building with the reason. Default: the host triple (`rustc -vV`'s `host:`).
- `install.sh` only when a darwin or linux target is built.
- Extend `tests/fixtures/cargo-app/` (T-02) only if needed; tests `tests/test_cargo_build.py` build the host target
  only, skipped when `cargo` is missing (as `test_go_build.py` does). `.github/workflows/test.yml`: add a Rust
  toolchain step to the pytest job, next to `setup-go`.
- README: `[connectors.cargo-build]` section and the Windows toolchain setup.
- Out of scope: signing and upload code (T-03 did the shared part), crates.io, installers.

## Contract
Roadmap → Contracts (config `[connectors.cargo-build]`, build command, Layout and manifest, `build` object, triple →
os/arch, Order). Refuses when `dist/` is not git-ignored (real run), when a toolchain piece is missing, or when a
target fails (no partial manifest).

## Decision (don't reopen)
- **Chosen:** linker follows from the triple (msvc → xwin, gnu → mingw); no `windows_linker` key.
- **Rejected:** `cross`/`cargo-zigbuild` for Linux targets, hosted-CI builds, a `VERSION` file or build-time
  version injection (`CARGO_PKG_VERSION` already stamps it).
- **Explicitly out of scope:** Authenticode; Linux cross-builds from macOS.

## Acceptance criteria (executable)
- [ ] Dry-run on the fixture (host target): one archive, `checksums.txt`, `manifest.json` matching the Layout, the
      `build` object filled; `shasum -a 256 -c checksums.txt` passes — `uv run --with pytest pytest tests/test_cargo_build.py -q`
- [ ] The host binary prints the planned version (`hello` → `0.1.0-rc0`) — same file
- [ ] A dirty working tree does not change the artifacts (built from the tag) — same file
- [ ] `cargo` missing → failed with the install hint; a target not installed → failed naming `rustup target add
      <t>`; a Linux triple from macOS → failed before building; a target that doesn't compile → failed, no manifest
      (required dependency failure criterion) — same file
- [ ] Windows on the maintainer's Mac: `release --dry-run` on the fixture with `targets = ["x86_64-pc-windows-msvc"]`
      (or the spike's path) produces `hello_0.1.0-rc0_windows_amd64.zip` and `.exe`, and `sign` + `github-release`
      in dry-run accept the manifest — the command and the manifest pasted in the Result
- [ ] go-build still passes (required regression criterion) — `uv run --with pytest pytest tests/test_go_build.py tests/test_sign.py -q`
- [ ] `release doctor` lists the cargo-build toolchain checks — `uv run --with pytest pytest tests/test_doctor.py -q`
- [ ] Lint and the full suite — `uvx ruff check . && uv run --with pytest pytest -q`
- [ ] Nothing private in the diff — `git diff origin/main --name-only | xargs grep -niEf <forbidden list from the brief>` finds nothing
- [ ] README section updated; tests follow the repo's test rules (`test-suite-prune`)
