# T-04: built-in `slack-notify` connector

- **Roadmap:** ../ROADMAP.md · **Phase:** 1 · **Repo:** release-cli · **Base branch:** release/jira-slack-p1 · **Branch:** feature/slack-notify
- **Depends on:** T-02 integrated (and T-03's result shape) · **Model:** sonnet

## Goal
`release connector add slack-notify`: the project's Slack channel gets one message per release that reached its target.

## Scope
- Files: new `release_cli/slack_notify.py`, `BUILTINS` in `connectors.py`, README section.
- Out of scope: Teams, bot tokens, threads/edits.

## Contract
Roadmap → Contracts (secrets, `[connectors.slack-notify]`, results in `prior`). Incoming webhook POST with Block Kit JSON, stdlib `urllib`.

## Behaviour
- `questions`: first time per project `webhook_secret` (text, persist; points at a secret name) and `notify_on`
  (choice `final` / `every-deploy`, default `final`, persist); one bool "Send the Slack notice?" default yes.
- `run`: honour `notify_on` and the deploy's SUCCESS in `prior`; message: repo, version, environment, deploy type,
  link to the GitHub Release (`prior.github-release.result.url`), the released Jira version and its delivered tickets (`prior.jira.result`),
  notes trimmed to Slack limits. Missing secret → `ok: false` with `release secret set <name>`.

## Acceptance criteria (executable)
- [x] Against a fake webhook (local `http.server`): payload content for final/RC, `notify_on` filtering, missing secret — `pytest tests/test_slack_notify.py -q`
- [x] The webhook URL is never printed or saved in run state — same file

## Result (filled by the worker)

- Built `release_cli/slack_notify.py`, registered in `BUILTINS`, README section `slack-notify`, `tests/test_slack_notify.py` (13 tests, local fake webhook, fake secret via env, keychain lookups stubbed out).
- Criteria: `pytest tests/test_slack_notify.py -q` → 13 passed; `tests/test_connectors_contract.py tests/test_doctor.py tests/test_github_release.py` → 47 passed; `uvx ruff check .` → clean. The webhook URL appears in no result, error or stderr (asserted for success, HTTP 500 and connection refused).
- Decisions where the spec was silent:
  - `notify_on=final` means `mode == "fv"`; `every-deploy` also announces RCs. The "Send the Slack notice?" question gets `when notify_on == every-deploy` on an RC, so it is not asked when it could never send.
  - Deploy connector is read from `prior[config.deploy_connector or "platform-deploy"]` (same key as cursor-review): `status ok` and `result.status == "SUCCESS"`, with `environment` and `deploy_type` from that result. If it is absent from `prior` (no deploy connector) the notice goes out right after the push; present but failed, or not SUCCESS → `ok: true, sent: false, reason`.
  - Jira section only when `prior.jira.result.mode == "fv"`; lists issues with status `delivered` or `already` (summary only, no per-ticket link: the contract has no base URL). Version links to `result.url` when it is https.
  - Notes come from `github_release.release_notes` (the same text as `release notes <tag>`), trimmed to 2500 chars at a line boundary; tickets capped at 20 plus "…and N more". If notes cannot be built the message is sent without them.
  - Webhook must be `https` (plain `http` only for loopback, which the tests use).
  - Secret name defaults to `slack-webhook`; an invalid name or a missing secret → `ok: false` with `release secret set <name>`.
- Not covered: a deploy connector skipped with `applies: false` is not in `prior`, so it looks like "no deploy connector" and the notice still goes out. Also not exercised against a real Slack workspace (by design).
