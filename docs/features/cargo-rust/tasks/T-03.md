# T-03: Shared packaging: zip, bare binary, `sign` covers binaries

- **Roadmap:** ../ROADMAP.md · **Phase:** 1 · **Repo:** release-cli · **Base branch:** release/cargo-rust-p1 (PR targets it, not main) · **Branch:** refactor/shared-packaging
- **Depends on:** none · **Model:** sonnet · **Review tier:** read (provenance subjects and signature checks)

## Goal
Any builder connector (go-build today, cargo-build in T-04) produces the same layout with one shared module, can ship
reproducible `.zip` archives and a bare Windows `.exe`, and `sign` verifies and attests that exe like an archive.
Go releases come out byte-identical to today's.

## Scope
- New `release_cli/packaging.py` with what `go_build.py` holds privately today: `_sha256`, reproducible tar.gz
  (`_add`, `_archive`), the worktree checkout at the tag (`_build`'s `git worktree add/remove/prune`), the `dist/`
  git-ignore guard and output-folder swap from `run`, `checksums.txt` + `manifest.json` writing and the
  "nothing reaches the output folder until every target built" rule from `_package`. Public names, docstrings.
- New in it: a reproducible zip writer (sorted entries, fixed `date_time` 1980-01-01, fixed `external_attr`
  (0o755 for the exe, 0o644 for the rest), `ZIP_DEFLATED`), and support for `kind: binary` entries (with `os`,
  `arch`) in checksums and manifest.
- `go_build.py` uses the module; its behaviour and output do not change.
- `sign.py`: `statement` subjects, `_check_on_disk` and line 333's subject list include `kind: binary`; the
  attestation sample stays an archive; messages "run go-build again" / "the go-build manifest" become builder-neutral
  ("run the build connector again"). `homebrew_tap.py`: confirm it ignores `.zip` / `binary` entries (Windows
  isn't a formula target); change it only if it doesn't.
- README: the layout table gains the `.zip` and `binary` rows.
- Out of scope: cargo anything (T-02, T-04), `github-release` (it already uploads every non-npm entry; confirm with a
  test, don't change it).

## Contract
Roadmap → Contracts → Layout and manifest (zip and exe names, `kind: binary`, `checksums.txt` lists archives and
binaries).
- **Non-functional:** go-build output byte-identical for the same commit (same checksums); provenance for an existing
  go release unchanged (no `binary` entries there).

## Decision (don't reopen)
- **Chosen:** extract and share — two builders must not drift on the layout `sign`, `github-release` and
  `homebrew-tap` rely on.
- **Rejected:** copying the helpers into `cargo_build.py`; a generic "builder base class". Plain functions.
- **Explicitly out of scope:** Authenticode signing; bare binaries for non-Windows targets.
