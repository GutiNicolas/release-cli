# T-02: `go` tool: detection and `VERSION` file

- **Roadmap:** ../ROADMAP.md · **Phase:** 1 · **Repo:** release-cli · **Base branch:** release/go-apps-p1 (PR targets it, not main) · **Branch:** feature/go-tool
- **Depends on:** T-01 integrated · **Model:** sonnet · **Review tier:** evidence

## Goal
`release --init` in a folder with `go.mod` sets up a Go app whose version lives in a `VERSION` file, and
`release -rc` / `-fv` / `hotfix` work exactly as for the other tools, tagging `vX.Y.Z`.

## Scope
- Files: `config.py` (`Tool` adds `go`), `detect.py` (`go.mod` is a marker, no longer an unsupported hint), new
  `adapters/go.py` (reads/writes the one-line `version_file`, default `VERSION`; artifact = last element of the
  module path in `go.mod`), `adapters/__init__.py`, `init.py` (creates `VERSION` with `0.1.0-SNAPSHOT` when missing,
  after asking; sets `tag_format = ["v{version}"]`; offers `go test ./...` as a before hook), `doctor.py` (`go` on
  PATH, `VERSION` readable).
- Out of scope: building anything (T-04).

## Contract
Roadmap → Contracts (project config). `VERSION` holds one line, `X.Y.Z[-rcN][-SNAPSHOT]`, trailing newline kept.
Anything else in the file is refused with the line it read.

## Acceptance criteria (executable)

- [ ] `-rc` twice then `-fv` on a real repo with a bare remote: tags `v0.1.0-rc0`, `v0.1.0-rc1`, `v0.1.0`; `VERSION` ends at `0.1.0-SNAPSHOT`; `--dry-run` shows the `VERSION` diff — same file

- **Decisions** (not spelled out in the spec):
  - **Initial version is `0.0.0-SNAPSHOT`, not `0.1.0-SNAPSHOT`.** Scope said `0.1.0-SNAPSHOT`, but the criteria need `-rc` to give `v0.1.0-rc0`, and `-rc` from any non-RC version starts the *next minor* (existing behaviour, shared by every tool): from `0.1.0-SNAPSHOT` it gives `0.2.0-rc0`. I kept the criteria and changed the seed. An existing `VERSION` is never touched.
  - If the user declines creating `VERSION`, init is cancelled (a Go project cannot release without it) instead of writing a config that fails at the first release.
  - The `go test ./...` offer defaults to **no**, so `--defaults` / non-interactive init still writes no hooks (the existing `AutoPrompter` contract).
  - Artifact: a trailing major-version element is skipped (`github.com/acme/tools/v2` → `tools`), since `v2` names nothing; the spec said "last element". Falls back to the folder name without a `module` line.
  - `VERSION` is strict: exactly `X.Y.Z[-rcN][-SNAPSHOT]` plus at most one line ending; a missing trailing newline or CRLF is kept as found. Anything else (leading `v`, two lines, empty file) is refused with the line read. Written values are checked too.
  - `release doctor` reports a missing `go` as a **warning**, not a failure: this task builds nothing, and only hooks need it. `VERSION` readability reuses the existing "project version" check.
  - `init` only creates `VERSION`; it does not commit it. The first release needs a clean tree, so the user commits `VERSION` (the init log and README say so).
  - `--init` with a `go.mod` next to another marker (e.g. a `pom.xml`) now asks which tool, like any multi-tool folder.
