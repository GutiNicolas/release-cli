# T-08: `sign` connector: cosign signature and SLSA provenance

- **Roadmap:** ../ROADMAP.md · **Phase:** 3 · **Repo:** release-cli · **Base branch:** release/go-apps-p3 (PR targets it, not main) · **Branch:** feature/sign
- **Depends on:** phase 2 merged · **Model:** sonnet · **Review tier:** read

## Goal
Anyone can check that a release's archives come from the maintainer and from the tagged commit, using a public key
the app publishes, without a hosted CI. It works the same on a laptop and in a local CI run.

## Scope
- Files: new `release_cli/sign.py` (built-in, entry point `sign`, declares `dry_run: safe`), `github_release.py`
  (uploads the new manifest entries), README section (how to verify, with the `cosign verify-blob` and
  `cosign verify-blob-attestation` commands), the go fixture.
- Runs after `go-build`: signs `checksums.txt` (`cosign sign-blob --key`, bundle `checksums.txt.sig`), writes an
  in-toto statement with a SLSA provenance predicate (subjects: every archive and its sha256; builder: release-cli
  and its version; source: repo, tag, commit; build flags from `[connectors.go-build]`) and signs it
  (`cosign attest-blob --key`, `<binary>_<version>.intoto.jsonl`), copies the public key as `cosign.pub`, and adds
  the three to the manifest.
- Keys: private key from secret `cosign-key` (PEM content), password from secret `cosign-password`, both through
  `release secret` (`RELEASE_SECRET_*` in a local CI). Written to a 0600 temp file only while cosign runs, then
  deleted. Public key path in config: `[connectors.sign] public_key = "cosign.pub"` (committed in the app repo).
  No transparency-log upload by default (`tlog = false`), so nothing about the maintainer is published.
- Dry-run: signs with a throwaway key generated in the temp dir, so the whole chain is checked without the real key.
- First step: confirm with cosign's docs that `attest-blob` / `verify-blob-attestation` with a key and no tlog work
  as above, and that npm provenance and GitHub attestations cannot be produced outside a hosted CI; record it in Result.
- Out of scope: CI-identity provenance (T-10).

## Contract
Roadmap → Decisions (provenance), Contracts (Layout, order, secrets). Result: `{"signed": [names], "public_key",
"tlog": false}`. Missing `cosign` → failed with the install hint; missing secret → failed with the
`release secret set` command; the key value never appears in output, run state or `prior`.

## Acceptance criteria (executable)
- [ ] Dry-run on the fixture: `cosign verify-blob --key cosign.pub --bundle checksums.txt.sig checksums.txt` and `cosign verify-blob-attestation --key cosign.pub --type slsaprovenance ...` pass for every archive; a tampered archive fails — `pytest tests/test_sign.py -q` (skips with a reason when `cosign` is missing; CI installs it)
- [ ] The provenance statement names the tag, commit and every archive's sha256 — same file
- [ ] Missing secret and missing `cosign` fail with their hints; the key never appears in captured output or the run file — same file
- [ ] `github-release` uploads the three new files — `pytest tests/test_github_release.py -q`
- [ ] Lint and the full suite — `uvx ruff check . && uv run --with pytest pytest -q`
