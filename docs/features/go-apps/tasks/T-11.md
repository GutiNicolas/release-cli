# T-11: `sign`: configurable provenance builder id

- **Roadmap:** ../ROADMAP.md · **Phase:** 4 · **Repo:** release-cli · **Base branch:** release/go-apps-p4 (PR targets it, not main) · **Branch:** feature/sign-builder-id
- **Depends on:** phase 3 merged · **Model:** sonnet · **Review tier:** read

## Goal
An app can publish its provenance statement without naming the tool that built it. Today `sign` writes the tool's
repo URL as `runDetails.builder.id`, keys `runDetails.builder.version` by the tool's package name and derives
`buildDefinition.buildType` from the tool's repo URL. An app whose release files must stay neutral sets one value.

## Scope
- Files: `release_cli/sign.py`, its tests, README (`[connectors.sign]` block and the provenance row of the layout
  table).
- New optional key `builder_id` under `[connectors.sign]`: an `https://` URL (refuse anything else with a hint, like
  the other config errors). When set:
  - `runDetails.builder.id` = `builder_id`;
  - `buildDefinition.buildType` = `<builder_id>/go-build/v1`;
  - `runDetails.builder.version` is omitted (it is optional in SLSA v1), so the tool's name appears nowhere.
- When unset: the statement is byte-for-byte what it is today (default unchanged).
- Fixtures use `https://github.com/acme/*`.
- Out of scope: the cosign bundle format, `github-release`, anything else in the statement.

## Acceptance criteria (executable)
- [ ] With `builder_id = "https://github.com/acme/app"` on the Go fixture's dry-run, the decoded statement (decode as

  `grep -iE 'release-cli|gutinicolas'` over it finds nothing — a test, and run once by hand
- [ ] Without `builder_id` the statement is unchanged (a test compares it with the current shape)

### Decisions
- A trailing `/` in `builder_id` is stripped, so `buildType` never has `//` (the spec said `<builder_id>/go-build/v1`). The id in the statement is the stripped value.
- Only the scheme (`https`) and a host are checked; no check that the URL points anywhere real.
- `builder_id` is validated whenever `[connectors.sign]` is read, so a bad value fails a dry-run too.
